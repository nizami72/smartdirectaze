
# Требования к странице Event

## Основная информация

Страница должна отображать основную информацию о мероприятии:

* Название мероприятия.
* Тип мероприятия.
* Описание.
* Дата и время начала.
* Дата и время окончания.
* Место проведения.

## Статус мероприятия

Страница должна отображать текущий статус мероприятия.

Поддерживаемые статусы:

* Draft
* Published

## Видимость

Страница должна отображать уровень доступа к мероприятию.

Поддерживаемые варианты:

* Public
* Private

## Информация об организаторе

Страница должна содержать информацию об организаторе мероприятия:

* Имя организатора.
* Телефон организатора.
* Email организатора.

## Гости

Страница должна отображать краткую информацию о гостях:

* Общее количество гостей.
* Количество отправленных приглашений.
* Количество подтверждений.
* Количество ожидающих ответа.
* Количество отказов.

Страница не должна отображать полный список гостей.

Для управления гостями должна использоваться отдельная страница.

## Дополнительная информация

Страница должна отображать заметки (Notes), связанные с мероприятием.

## Действия

На странице должны присутствовать основные действия:

* Edit Event
* Delete Event
* View Guests
* Send Invitations


# Требование: Отображение гостей на странице Event

* Страница **Event** должна отображать только краткую информацию о мероприятии.
* На странице **не должен** отображаться полный список гостей.
* Вместо списка должна отображаться краткая статистика по гостям, например:

    * Всего гостей
    * Приглашения отправлены
    * Подтвердили участие
    * Ожидают ответа
    * Отказались
* На странице должна быть кнопка **View Guests** (или **Manage Guests**).
* При нажатии на кнопку открывается отдельная страница управления гостями мероприятия.

## Страница Event Guests

Отдельная страница должна предоставлять полный функционал управления гостями:

* просмотр списка гостей;
* поиск;
* сортировка;
* фильтрация;
* отметка присутствия;
* массовые операции;
* отправка сообщений через WhatsApp;
* переход в карточку гостя.

## Ограничения UX

* Не использовать **dropdown** для отображения списка гостей, так как он предназначен для небольших наборов данных.
* Не отображать полный список гостей непосредственно на странице **Event**, поскольку мероприятия могут содержать сотни гостей, что перегружает интерфейс и ухудшает восприятие основной информации о мероприятии.

## архитектурное правило проекта

Каждая доменная сущность имеет один Page Component. Этот компонент поддерживает три режима работы: Create, View и Edit.

Это дает несколько преимуществ:

одинаковое поведение во всем приложении;
меньше компонентов и маршрутов;
меньше дублирования кода;
пользователю проще ориентироваться, потому что все сущности работают одинаково.

Мне кажется, это первое правило интерфейса, которое стоит зафиксировать в архитектуре проекта и затем не нарушать без очень веской причины. Оно достаточно простое, чтобы его понимал любой новый разработчик команды, и при этом хорошо масштабируется на все будущие модули.

Для каждой доменной сущности существует одна страница списка (List Page).
Для каждой доменной сущности существует одна страница объекта (Entity Page).
