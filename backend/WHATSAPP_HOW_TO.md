Когда новый бизнес регистрируется в вашей системе, **знать только его номер телефона на старте недостаточно** — номер сам по себе не передается в Green API при создании инстанса. Номер привязывается **позже**, в момент сканирования QR-кода.

Процесс получения `idInstance` и `apiTokenInstance` и привязки номера клиента состоит из 4 четких шагов:

---

### Step 1. Создание инстанса через Partner API (Backend)

Поскольку вы создаете инстансы динамически для своих клиентов, вы используете **Partner API** Green API. Ваш бэкенд делает HTTP-запрос, используя ваш главный **Partner Token** (токен вашего мастер-аккаунта Smart Direct):

```http
POST https://api.green-api.com/partner/createInstance
Content-Type: application/json
Authorization: Bearer <YOUR_PARTNER_TOKEN>

```

**Ответ от Green API:**

```json
{
  "idInstance": "7107123456",
  "apiTokenInstance": "a1b2c3d4e5f67890..."
}

```

> **Что делать в базе данных:** Вы сразу сохраняете эту пару (`idInstance`, `apiTokenInstance`) в таблицу профиля этого бизнеса в вашей БД. На этом этапе инстанс уже создан, но к нему еще **не привязан** WhatsApp.

---

### Step 2. Настройка Webhook URL (Backend)

Сразу после создания инстанса ваш бэкенд выставляет этому инстансу настройки для отправки вебхуков в вашу систему:

```http
POST https://7107.api.greenapi.com/waInstance7107123456/SetSettings/a1b2c3d4e5f67890...
Content-Type: application/json

{
  "webhookUrl": "https://qrfood.az/api/v1/webhooks/whatsapp",
  "incomingWebhook": "yes",
  "stateWebhook": "yes"
}

```

---

### Step 3. Генерация QR-кода (Frontend)

1. Ваш бэкенд запрашивает QR-код для этого инстанса:
```http
GET https://7107.api.greenapi.com/waInstance7107123456/qr/a1b2c3d4e5f67890...

```


2. Green API возвращает строку Base64 или картинку QR-кода, которую вы отображаете на экране в личном кабинете Smart Direct.

---

### Step 4. Сканирование и привязка телефона (Пользователь)

1. Клиент открывает свой WhatsApp на телефоне $\rightarrow$ **Связанные устройства** $\rightarrow$ **Привязка устройства**.
2. Клиент сканирует QR-код с экрана вашeго сервиса.
3. В момент сканирования происходит **авторизация**: Green API связывает WhatsApp-сессию данного номера с `7107123456`.
4. Green API отправляет вам вебхук изменения состояния (`stateInstance` $\rightarrow$ `authorized`).
5. Вы можете сделать запрос `GetSettings` или `GetAuthorizationCode`, чтобы убедиться, что аккаунт авторизован, и записать номер телефона в профиль пользователя, если его там еще не было.

---

### По поводу номера телефона клиента:

Если вы **уже знаете** номер телефона клиента заранее (он ввел его при регистрации), вы также можете использовать альтернативный метод — **авторизацию по номеру телефона (Pairing Code)** вместо QR-кода:

1. Вы вызываете метод `sendRegistrationCode`, передавая номер телефона клиента.
2. WhatsApp отправляет 8-значный код прямо в приложение WhatsApp на телефоне клиента.
3. Клиент вводит этот код на вашем сайте — и инстанс становится авторизованным без сканирования QR-кода.

Списание средств происходит **в момент вызова метода создания инстанса** (т.е. при отправке запроса `POST /partner/createInstance`), а **не** в момент сканирования QR-кода.

---

### Как это работает под капотом:

1. **Создание инстанса = Покупка ресурса:**
   Как только вы отправляете запрос к Partner API на создание инстанса, Green API выделяет под вас контейнер/виртуальный инстанс на своих серверах. В этот же момент с вашего баланса списывается абонентская плата за 30 дней.
2. **Состояние "Unauthorized" (До сканирования):**
   Инстанс уже существует, у него есть `idInstance` и `apiTokenInstance`, за него уже оплачен месяц, но он находится в ожидании авторизации (`stateInstance: "notAuthorized"`).
3. **Сканирование QR-кода = Авторизация:**
   Привязка телефона (сканирование QR-кода или ввод Pairing Code) меняет только статус внутри уже созданного и оплаченного инстанса на `authorized`. Никаких дополнительных списаний в этот момент не происходит.

---

> **Важно для бизнес-логики Smart Direct:**
> Чтобы вы не платили за "заброшенные" или случайно созданные инстансы, создавайте инстанс в Green API **только тогда, когда пользователь нажал кнопку «Подключить WhatsApp»**, а не автоматически при регистрации пользователя на вашем сайте.



**Вы абсолютно можете переиспользовать этот инстанс для другого клиента.**

Поскольку деньги уже списаны с вашего баланса за 30 дней работы инстанса, Green API не возвращает средства за неиспользованные дни. Но сам инстанс (пару `idInstance` и `apiTokenInstance`) можно легко привязать к совершенно другому номеру телефона.

---

### Как переиспользовать инстанс для другого клиента:

Вам не нужно удалять инстанс и платить за новый. Достаточно выполнить 3 шага в бэкенде:

#### 1. Выйти из старого WhatsApp-аккаунта (LogOut)

Вызываете метод `Logout`, чтобы разорвать сессию с телефоном ушедшего клиента:

```http
GET https://7107.api.greenapi.com/waInstance7107123456/logout/a1b2c3d4e5f67890...

```

Статус инстанса сменится на `notAuthorized`. Старый клиент больше не связан с этим инстансом.

#### 2. Перепривязать инстанс к новому клиенту в вашей БД

В своей базе данных вы просто отвязываете этот `idInstance` от ушедшего пользователя и прикрепляете его к новому клиенту Smart Direct, который только что оформил подписку.

#### 3. Авторизовать новый номер

Генерируете QR-код (или Pairing Code) для этого же инстанса и показываете его **новому** клиенту. Он сканирует код — и оставшиеся оплаченные дни инстанса работают уже на нового пользователя.

---

### Стратегия управления инстансами ("Пул инстансов")

Для Smart Direct выгодно держать в базе концепцию **пула свободных (сброшенных) инстансов**:

```text
[Оплаченный инстанс в Green API] 
       │
       ├── Занят пользователем А ──(Клиент ушел)──> Logout + Сброс в БД
       │                                                   │
       └── Переназначен пользователю Б <──(Экономия $12)───┘

```

* **Если клиент уходит:** вы делаете `Logout`, очищаете привязку в своей БД и помечаете этот `idInstance` как `FREE` (свободный).
* **Когда приходит новый клиент:** ваш бэкенд сначала проверяет, есть ли в БД инстансы со статусом `FREE` с неистекшей оплатой. Если есть — вы отдаете его новому клиенту без вызова `createInstance` и без лишних списаний с депозита.
