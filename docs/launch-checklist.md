<a id="server"></a>
## 1. Сервер

- [x] **1.1 👤 Выложить текущий master**
  ```bash
  bash deploy/deploy.sh
  ```
  Готово, когда в конце `backend is up`, а в ответе версии `"commit"` без `-dirty`.


- [x] **1.2 👤 Включить профиль `prod` (новый systemd-юнит)**
  ```bash
  scp -i ~/.ssh/key2 deploy/smartdirect.service root@157.180.16.28:/etc/systemd/system/smartdirect.service
  ssh -i ~/.ssh/key2 root@157.180.16.28 'systemctl daemon-reload && systemctl restart smartdirect && sleep 40 && curl -s http://127.0.0.1:8083/webhooks/w/alive'
  ```
  Готово, когда ответ `"status":"UP"`. Если нет: `journalctl -u smartdirect -n 50 --no-pager`.


- [x] **1.3 👤 Поставить автоматическую проверку (сообщения в Telegram)**
  ```bash
  scp -i ~/.ssh/key2 deploy/healthcheck.sh root@157.180.16.28:/opt/smartdirect/healthcheck.sh
  ssh -i ~/.ssh/key2 root@157.180.16.28 'chmod 755 /opt/smartdirect/healthcheck.sh && (crontab -l; echo "* * * * * /opt/smartdirect/healthcheck.sh") | crontab -'
  ```
  Проверка: остановить сервис на 3 минуты (`systemctl stop smartdirect`), должно прийти «🔴 SmartDirect: …», после `systemctl start smartdirect` — «🟢 SmartDirect снова работает».


- [x] **1.4 👤 Остановить и запустить SmartDirect вручную**

  Остановить:
  ```bash
  ssh -i ~/.ssh/key2 root@157.180.16.28 systemctl stop smartdirect
  ```

  Запустить:
  ```bash
  ssh -i ~/.ssh/key2 root@157.180.16.28 systemctl start smartdirect
  ```

  Перезапустить:
  ```bash
  ssh -i ~/.ssh/key2 root@157.180.16.28 systemctl restart smartdirect
  ```

  Состояние:
  ```bash
  ssh -i ~/.ssh/key2 root@157.180.16.28 systemctl status --no-pager smartdirect
  ```
  Старт занимает ~15 секунд. Пока сервис остановлен, AI не отвечает покупателям.


- [ ] **1.5 👤 Копия бэкапов вне сервера**
  Выбрать: Hetzner Storage Box (~3 €/мес) или ваш ноутбук (cron с `rsync` раз в сутки). Настройку скрипта сделает 🤖, когда выберете.


- [ ] **1.6 👥 Проверить восстановление из бэкапа**
  Один раз восстановить вчерашний бэкап на копию базы и убедиться, что данные на месте (команды в [how-to.md, раздел 11](how-to.md#backup)).

## 2. Код: что мешает мерчанту

- [x] **2.1 🤖 Проверка формата номера** (0.2.0, выложено)
  В «Тестовых номерах» и «Уведомлениях о заказах»: азербайджанский номер = 12 цифр, начинается с `994`; иначе подсказка, что не так. (Сегодня тестовый номер `9944679933` записался без `50`, и AI молчал.)


- [x] **2.2 🤖 Номер для уведомлений по умолчанию** (0.2.0, выложено)
  Подставлять личный номер из регистрации; если поле пустое — предупреждение «уведомления приходят в чат „Вы“ без звука».


- [x] **2.3 🤖 Предупреждение о риске блокировки перед QR** (0.4.0)
  Блок «Перед подключением» с галочкой «Я понимаю риск», QR только после неё; согласие сохраняется в базе с датой. В подтверждение «Для всех» — фраза про рассылки незнакомым.


- [ ] **2.4 🤖 Понятные ошибки Green API в логах**
  Сейчас при сбое пишется только «operation failed». Добавить причину (метод, код ответа), без текста сообщений.


- [ ] **2.5 🤖 Кнопка «Написать в поддержку»**
  Задать `VITE_SUPPORT_WHATSAPP` в `frontend/.env.production`. 👤 нужен номер поддержки.

- [x] **2.6 🤖 Кнопка «Отправить тестовое уведомление»** (0.2.0, выложено)
  Рядом с полем «Уведомления о заказах»: магазин сам пишет на этот номер «Это номер для уведомлений SmartDirect ✅». Пришло — номер верный. Вместо OTP: отправляет инстанс магазина своему владельцу, риска блокировки нет.
