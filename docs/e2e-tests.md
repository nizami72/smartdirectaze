<a id="overview"></a>
## 1. Что есть в проекте

| Что | Где |
|---|---|
| Конфиг | `frontend/playwright.config.ts`: тесты в `e2e/`, адрес сайта из `E2E_URL` (по умолчанию `http://localhost:5173`), только Chromium, снимок экрана при падении |
| Тесты | `frontend/e2e/*.spec.ts` — регистрация, вход/выход, язык AZ/RU, создание магазина, панель магазина, тестовый чат AI |
| Общая подготовка | `frontend/e2e/fixtures.ts` (фикстура `merchantPage` — уже зарегистрированный и вошедший мерчант), `frontend/e2e/support/` (регистрация, вход, создание магазина, тексты интерфейса) |
| Отчёты | `frontend/test-results/`, `frontend/playwright-report/` (в git не попадают) |

Тест тестового чата помечен **`@ai`**: он обращается к настоящей модели DeepSeek (нужен ключ `DEEPSEEK_API_KEY` у бэкенда, доли цента за прогон).

Каждый прогон регистрирует новых мерчантов с почтами `test<цифры>@example.com` и создаёт их магазины.

<a id="prepare"></a>
## 2. Перед запуском: поднять сайт

Тесты работают с уже запущенным сайтом. Локально:

1. Бэкенд — в IntelliJ (порт 8080).
2. Фронт:
   ```bash
   cd frontend && npm run dev
   ```
   Сайт на `http://localhost:5173`.

<a id="cli"></a>
## 3. Запуск из терминала

Из папки `frontend/`:

| Команда | Что делает |
|---|---|
| `npm run e2e` | Все тесты, без окна браузера |
| `npm run e2e:watch` | Все тесты в видимом окне Chromium, по одному, с паузой 0.5 с перед каждым действием |
| `npm run e2e:ui` | Окно Playwright UI: выбор тестов, шаги, запись |
| `npm run e2e:headed` | Видимое окно без паузы |
| `npm run e2e:no-ai` | Все, кроме тестов `@ai` |
| `npm run e2e:ai` | Только тесты `@ai` |
| `npm run e2e:ai:watch` | Только `@ai`, видимое окно, пауза 0.5 с |
| `npx playwright show-report` | Открыть HTML-отчёт последнего прогона |

Настройки через переменные окружения:

| Переменная | Пример | Что делает |
|---|---|---|
| `E2E_URL` | `E2E_URL=https://smartdirect.qrfood.az npm run e2e` | Адрес сайта |
| `E2E_SLOWMO` | `E2E_SLOWMO=1000 npx playwright test --headed` | Пауза перед каждым действием, мс |
| `E2E_SKIP_AI` | `E2E_SKIP_AI=1 npm run e2e` | Пропустить тесты `@ai` |

Один файл или один тест: `npx playwright test e2e/dashboard.spec.ts`, `npx playwright test -g "wrong password"`.

<a id="vscode-install"></a>
## 4. Расширение VS Code: установка

1. В VS Code: панель расширений (`Ctrl+Shift+X`) → **«Playwright Test for VS Code»** от **Microsoft** → Install.
2. Открыть папку репозитория `smartdirectaze` целиком (File → Open Folder).
3. Браузеры ставить не нужно: Chromium уже скачан (`~/.cache/ms-playwright`), `@playwright/test` стоит во `frontend/`.

**Две особенности этого проекта:**

- **Конфиг не в корне**, а в `frontend/playwright.config.ts`. Расширение обычно находит его само. Если тесты не появились: панель **Testing** (иконка колбы) → блок **Playwright** внизу → в списке **Configs** отметить `frontend/playwright.config.ts`.
- **Node.js.** Системный Node 18 устарел, проект работает на Node 22 из nvm. Если расширение ругается на запуск или версию Node — открыть VS Code из терминала с Node 22:
  ```bash
  nvm use 22 && code ~/projects/java/smartdirectaze
  ```
  или один раз сделать 22 версией по умолчанию: `nvm alias default 22`.

<a id="vscode-tests"></a>
## 5. Где увидеть тесты

Боковая панель **Testing** (колба слева): дерево `e2e/` → файлы (`registration.spec.ts`, `dashboard.spec.ts`, …) → группы `describe` → отдельные тесты.

Под деревом — блок **Playwright** с настройками:

- **Show browser** — тесты идут в видимом окне Chromium (как `--headed`);
- **Show trace viewer** — после прогона открывается пошаговая запись: снимки страницы, клики, сетевые запросы.

<a id="vscode-run"></a>
## 6. Как запустить один тест

Сначала поднять сайт ([раздел 2](#prepare)).

- **В файле:** открыть, например, `e2e/dashboard.spec.ts`. Слева от каждого `test(...)` — зелёный треугольник ▶: щелчок — запуск, правый щелчок → **Debug Test** (с точками останова). После прогона рядом появится ✓ или ✗.
- **В панели Testing:** навести на тест в дереве → ▶. На файле или папке ▶ запускает всё внутри.

Учтите:

- «Запустить всё» запустит и тест `@ai` (запросы к DeepSeek). Исключить его: в поле фильтра панели Testing ввести `!@ai`.
- **Пауза 0.5 с, как в `npm run e2e:watch`:** в настройках VS Code (`Ctrl+,` → Open Settings JSON) добавить и включить **Show browser**:
  ```json
  "playwright.env": { "E2E_SLOWMO": "500" }
  ```
  Там же можно направить тесты на сервер: `"E2E_URL": "https://smartdirect.qrfood.az"` (см. [раздел 9](#server)).

<a id="vscode-record"></a>
## 7. Как записать новый тест (Record new)

1. Сайт запущен ([раздел 2](#prepare)).
2. Панель **Testing** → блок **Playwright** → **Record new**.
3. Расширение создаст `frontend/e2e/test-1.spec.ts` и откроет окно Chromium.
4. В адресной строке этого окна ввести `http://localhost:5173/register` (или нужную страницу) и просто работать с сайтом — каждый клик и ввод сразу записывается в файл как код.
5. Панель записи вверху окна:
   - **Assert visibility / text / value** — щёлкнуть по элементу, в тест добавится проверка;
   - **Pick locator** — показывает, как Playwright найдёт элемент.
6. Закрыть окно браузера — запись остановится. Переименовать файл по смыслу, например `e2e/orders.spec.ts`.

**Record at cursor:** поставить курсор внутрь существующего теста — записанные шаги вставятся туда.

<a id="style"></a>
## 8. Как писать тесты в стиле проекта

Записанный тест работает, но его стоит поправить:

| Записано | Заменить на | Зачем |
|---|---|---|
| `page.goto('http://localhost:5173/register')` | `page.goto('/register')` | Тест работает и против сервера через `E2E_URL` |
| Ручные шаги регистрации и входа | `import { test, expect } from './fixtures'` и `async ({ merchantPage, merchant })` | Готовый вошедший мерчант |
| Создание магазина вручную | `await createShopAndOpenDashboard(page)` (из `./support/merchant`) | Магазин с открытой панелью, возвращает его номер |
| Добавление товара вручную | `await addProduct(page, 'Название', '45')` | Ждёт появления карточки |
| Постоянная почта `test@…` | `newMerchant()` | Иначе второй прогон упадёт на «почта уже занята» |
| Азербайджанский текст как есть | `text('az', 'ключ')` из `./support/texts` (ключи — `src/i18n/az.json`); ошибки сервера — `serverText('az', 'error.…')` | Тест не сломается, когда поправят перевод |
| Селектор по CSS-классу | `page.getByTestId('…')` | Классы меняются при правке дизайна |

Если нужному элементу не хватает надёжного селектора — добавить ему атрибут `data-testid` в компоненте React (или в шаблоне `product-list.html` для страницы «Товары и доставка»).

Тест, который обращается к AI, помечать тегом: `test.describe('…', { tag: '@ai' }, () => { … })`.

<a id="server"></a>
## 9. Прогон против сервера и очистка

```bash
cd frontend && E2E_URL=https://smartdirect.qrfood.az npx playwright test --reporter=list,html
```

- Тесты создают на сервере настоящих пользователей и магазины; оператору в Telegram приходят сообщения о каждой регистрации и каждом новом магазине.
- Не выкладывать новую версию во время прогона: тесты, начавшиеся на старом фронте, упадут.
- Снимки упавших шагов — `frontend/test-results/*/test-failed-1.png` и в HTML-отчёте.

**Очистка после прогона** — удалить пользователей `test<цифры>@example.com` и их магазины, не трогая остальные данные. Делалась 2026-10-03 (22 пользователя, 12 магазинов): сначала копия базы `before-cleanup_*.sql.gz`, затем одна транзакция — тестовые номера и каналы этих магазинов, переписки, заказы, товары с их переводами и фото, магазины, записи бизнесов, которыми больше никто не пользуется, профили и сами пользователи. Отдельного скрипта пока нет (пункт в [todo.md](../todo.md) «Скрипт удаления только тестовых аккаунтов»).
